About synthunits

synthunits (单元, "unit, module") is a series of little Eurorack building blocks. I'm Jeremy Seitz, a maker and engineer in Luzern, Switzerland, and this is my project.

The idea

I wanted to try synth ideas on real boards quickly, and turn the good ones into modules. So the circuits are drawn once, as blocks: an oscillator core, a filter, a VCA, an envelope, a mixer, power entry, CV input for a microcontroller. A board is a few blocks put together. When a block improves, every board that uses it does too.

  • One module, one board. Each can be powered, probed and fixed on its own before it joins the others.
  • Leads, not a panel, at first. Every jack, pot and switch has its own JST connector with a fixed pinout, so a board can sit in a box on the bench with its controls on leads, then go behind a front panel when it works.
  • Parts a fab can place. The circuits are analog, discrete or op-amp and OTA designs, built from surface-mount parts the board house stocks and assembles. Dedicated synth chips get their own breakouts to compare.
  • One look. Black panels on one shared layout, the knobs coloured by their job (orange for frequency, light grey for amounts, ivory for times, white for levels), mono LEDs whose colour says what they show, and an icon for each module after Patch & Tweak's patch symbols.

How it's made

The blocks, the boards' schematics and placement, the panels, the checks and this site are generated by scripts in KiCad, so the boards and the documents describe the same thing. I write and run them with Claude Code as a working partner; the shared KiCad tooling is pcb-kit. The research behind the circuits came from published designs and datasheets: each block notes what it follows and redraws it rather than copying it.

Open source?

Not yet. I may open the library once the circuits are proven, but I don't want to commit to a design in public before I've built it. Until then this site shows the schematics, the boards and how they're wired, without files to download.

Feedback

I'd like to know what you think, and which modules you'd use. Everything happens in the open on GitHub (you need a GitHub account to take part):

  • Discussions: questions, ideas, what you'd patch with it, in the discussions.
  • "I'd use this": a thumbs-up on a module's tracking issue counts as interest. The interest form lets you tick several modules and say whether you'd want a kit or a built module.
  • Ask for a module: a module request: what it does and why you'd want it.
  • Something wrong on this site: open an issue.
